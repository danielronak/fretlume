# Spec 05 — UX, screens and visual identity

Originality rule: parity of *function* with the reference app, never of *appearance*. The reference
uses a teal gradient with brushed-metal panels and a serif display face; we deliberately do not.

## 1. Visual identity (design tokens in `app/src/ui/tokens.css`)
- **Mood:** a dim stage with warm light — the camera view is the hero, chrome stays out of the way.
- **Surfaces:** near-black warm charcoal `#141210`, raised `#1E1B18`, hairlines `#2E2A26`; light theme
  available (warm paper `#FAF7F2`). Flat surfaces, no metal textures, no gradients behind text.
- **Accent:** amber `#FFB000` (primary actions, root notes); secondary cyan `#4CC9F0` for information.
- **Type:** system UI stack for chrome; a geometric sans (bundle one open-licence variable font, e.g.
  Inter or Manrope, self-hosted) for headings; tabular numerals for frets/tempo.
- **Overlay palettes** (must be legible on wood, skin and clothing): saturated fills with a 2 px dark
  outline and white label text; root = accent with white ring. CAGED shapes: C `#2EC4B6`, A `#4361EE`,
  G `#B5179E`, E `#FF9F1C`, D `#E63946`. Inversions: root `#2EC4B6`, 1st `#B5179E`, 2nd `#FFB000`.
  Fingers 1–4: `#4CC9F0`, `#80ED99`, `#FFB000`, `#F72585`. Provide deuteranopia/protanopia-safe
  alternates and a shapes-not-colours option (circle/square/triangle/diamond per group).
- Motion: 150–200 ms eases; overlay never animates position (it must look glued to the neck) — only
  opacity/scale pulses on events.

## 2. Information architecture
Bottom bar on phones, left rail on desktop: **Today · Learn · Library · Stage · Tabs · Tools · Progress**; Settings
from the profile menu.

| Screen | Purpose | Key elements |

## 3. Stage: lock flow and messages
| State | What the player sees |
|---|---|
| No camera permission | Explanation card + "Use without camera" (flat diagram mode keeps every feature usable) |
| SEARCHING | Dimmed video, framing guide (a neck-shaped outline), tips cycling: "Show the whole neck", "More light", "Hands off the neck for a second"; buttons **Lock manually** |
| VERIFYING | Outline of the detected board + fret numbers 1·3·5·7·9·12 drawn on the neck; "Looks right?" **Yes** / **◄ shift fret ►** / **Adjust corners** |
| LOCKED/TRACKING | Overlay at full opacity; status pill green |
| RECOVERING | Overlay fades to 40 % and holds position; pill amber "Hold still…" |
| Lost | Back to SEARCHING with the previous pose as a ghost guide |
Manual lock: frozen frame, four numbered handles with a magnifier loupe, live preview of the fret grid,
**Done**. First-run coach marks explain framing with an illustration (our own drawing).

## 4. Overlay rendering rules
- Dot centre: finger target (spec 01 §2); radius = 0.36 × local string spacing × user scale (0.6–1.6);
  drawn as an ellipse using the local Jacobian of `H` so it sits flat on the board.
- Open strings: ring left of the nut; muted strings: small ✕ at the nut.
- Layers bottom → top: fret-range shading, ghost (neighbour-shape) dots at 35 %, main dots, labels,
  event pulses (correct = brief white ring; wrong = shake + the *expected* dot pulses), hand hints.
- When the fretting hand covers a dot, draw the dot outline only (so it does not paint over fingers)
  once hand tracking is on (Phase 7).
- Tab play-along: upcoming notes approach along the string from the bridge side as shrinking rings; the
  current note is solid; sustain shown as a tail. A "next chord" ghost appears one beat early.
- Performance: one Canvas2D layer at device pixel ratio ≤ 2; no layout work per frame.

## 5. Left-handed and mirroring
Two independent settings: **mirror view** (default on, like a mirror) and **string order flip** (left-handed
stringing). Lefty preset sets both appropriately; flat diagrams mirror too. Persisted.

## 6. Accessibility and input
Full keyboard operation (space = start/pause, ←/→ = back/next, L = loop, R = re-lock, M = mic);
foot-pedal friendly (page-turn pedals send arrow keys); screen-reader labels on all controls; captions
for audio feedback; optional spoken prompts via the Web Speech API where an offline voice exists;
minimum 44 px touch targets; reduced-motion respected.

## 7. Empty, error and permission states
Every screen has a designed empty state with one clear action. Permission denials explain how to
re-enable in the browser. Low-light and low-fps detectors suggest fixes. Nothing blocks the player
from continuing in flat-diagram mode.

## 8. Responsive layouts
Desktop ≥ 1024 px: rail + content; Stage deck floats. Tablet: same with larger targets. Phone
landscape (the realistic way to prop a phone at a guitar): Stage is full-bleed with a compact deck that
auto-hides; phone portrait is supported for Library/Learn/Tools. Stage requests a screen wake lock.
